## 一、为什么删

三条查证过的事实：

1. **`translationKey` 字段没有任何代码读取**。它只出现在 `src/content.config.ts` 的 schema 声明和 `public/admin/config.yml` 的字段定义里，路由、页面、RSS 全程没用到——写了也白写。
2. **英文内容只有 1 篇占位文**（`src/content/blog/en/hello-world.mdx`），中文侧有 12 篇。所谓"双语"没有内容支撑。
3. **导航栏的语言切换是假的**：`Header.astro` 里的 EN 按钮无论你在哪篇文章，都只是跳到首页，不保留当前文章。

结论：删掉后一篇只写一次，CMS 少一个集合，构建少一半页面，URL 也不再有 `/en/` 前缀这一个迷惑来源。

## 四、实现时的几个坑（都已处理）

1. **`getRelativeLocaleUrl()` 来自 `astro:i18n`，删掉 `i18n` 配置就会全部报错**。正确顺序是先把 11 处调用全部替换成普通路径，最后再删配置块。
2. **Astro 不允许动态重定向目标**。`'/en/[...path]': '/[...path]'` 会直接构建失败（`InvalidRedirectDestination`：目标必须匹配项目里已存在的路由），只能逐条列静态路径。
3. **重定向源带不带结尾斜杠会被归一化成同一条规则**：写成 `/en/about` 和 `/en/about/` 两条，产物里是两条一模一样的 `^/en/about$`（重复项），所以只写一条即可。
4. **`/about` 的 entry id 变了**：pages 集合 base 是 `src/content/pages`，拍平后 id 从 `zh/about` 变成 `about`。
5. **静态页里不能 `return Astro.redirect()`**：原 `about.astro` 的这段代码在构建期不会执行（entry 一直存在），现在改成 `throw new Error("缺少内容文件：src/content/pages/about.md")`，缺失时直接构建失败并给出人话提示。
6. **遗留路由隐患顺手消除**：原先 `[...lang]/about.astro` 会生成 `/en/about/`，而 `src/pages/en/about.md` 也生成 `/en/about/`，两个来源同名；随删除一并消失，现在构建无重复路由告警。

### 7.2 既有的、不是本次引入的问题

- **`npm run format:check` 是红的**：27 个文件报格式问题，其中包含本次完全没碰过的 `src/components/ThemeToggle.astro` 以及 11 篇内容 `.md`。原因是 Windows 检出后文件是 CRLF，而 prettier 默认 `endOfLine: lf`。本次没有跑 `prettier --write`，避免把整个内容库翻一遍制造无关 diff。想根治可以在 `.prettierrc` 里加 `"endOfLine": "auto"`，或统一做一次 `prettier --write src/`。
- **受限沙箱下 `astro build` 会报 `require is not defined`（picomatch）**：用改动前的 `7649aab` 复现过同样报错，确认与本次改动无关；放宽文件权限后构建正常。这不是项目问题，本地/Vercel 正常 `npm ci && npm run build` 不受影响。

### 7.3 环境备注

本次为了在受限环境里跑通构建，`node_modules` 是带 `--ignore-scripts` 安装的（仅供本次验证，且 `node_modules/` 已被 gitignore）。你本机建议照常跑一次 `npm ci` 做干净安装。
