> 基于《博文编写方案分析.md》与当前项目现状整理（双语言 `src/content/blog/{zh,en}/`、COS 图床已就绪、Vercel 部署）。

## 一、目标与架构

多种写博客方式并存，统一落到 GitHub 仓库，由 Vercel 检测变更自动构建：

```
┌──────────────────────────────┐
│ 写博客的几种入口              │
├──────────────────────────────┤
│ ① VSCode（现状，不动）        │──┐
│ ② Sveltia CMS（本次新增）     │──┤ 全部写入
│ ③ GitHub.dev / 网页编辑       │──┤
│ ④ Obsidian（P2 暂缓）         │──┘
└──────────────────────────────┘
              │
              ▼
   fartmonarch/astro_blog 仓库（src/content/blog/{zh,en}/*.md(x)）
              │
              ▼
        Vercel 检测 push → 自动构建部署
```

| 入口 | 状态 | 本次动作 |
|---|---|---|
| VSCode + Git Push（方案 A） | 已在使用 | 无 |
| GitHub 网页 / github.dev（方案 D） | 天然可用 | 无（写进日常流程） |
| Sveltia CMS（方案 C） | 未实现 | **P1 实现** |
| Obsidian（方案 B） | 未实现 | P2 暂缓（见附录三） |

## 二、P1：Sveltia CMS 实施步骤

### 2.0 前置检查

- [ ] `fartmonarch/astro_blog` 仓库存在，默认分支为 `main`
- [ ] 本地 `npm run dev` 可启动（`astro dev` 会把 `public/` 映射到站点根路径，`/admin/` 可直接访问）
- [ ] 已确认现有文章是纯 Markdown 内容（无 MDX 组件语法），见 2.4 风险表

### 2.1 准备 `public/admin/` 三个文件

```
public/admin/
├── index.html        ← 后台入口页
├── sveltia-cms.js    ← 官方单文件（v0.191.1，约 1.9MB，无需构建）
└── config.yml        ← CMS 配置
```

**下载 sveltia-cms.js**（GitHub Release 无独立资产，从 npm 包走 CDN 获取）：

```bash
curl -L -o public/admin/sveltia-cms.js https://cdn.jsdelivr.net/npm/@sveltia/cms@0.191.1/dist/sveltia-cms.js
```

**index.html**：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <meta name="robots" content="noindex" />
  <title>博客管理后台</title>
</head>
<body>
  <script src="sveltia-cms.js"></script>
</body>
</html>
```

**config.yml**（对照现有 `src/content.config.ts` 的 schema 逐字段映射）：

```yaml
backend:
  name: github
  repo: fartmonarch/astro_blog
  branch: main
  # 认证：GitHub Personal Access Token（登录页 "Sign In with Token"），无需 client_id，见 2.2

# 图片继续走 COS 图床外链，CMS 内不启用仓库图片上传
# （media_folder / public_folder 为满足配置要求而保留）
media_folder: "public/images"
public_folder: "/images"

site_url: https://fartmonarch.xyz

collections:
  - name: "blog-zh"
    label: "博客文章 · 中文"
    folder: "src/content/blog/zh"
    create: true
    delete: true
    extension: md
    format: frontmatter
    slug: "{{slug}}"
    editor:
      preview: false          # Astro 无现成预览 iframe，关闭避免报错
    fields:
      - { label: "标题", name: "title", widget: "string" }
      - { label: "描述", name: "description", widget: "text" }
      - { label: "发布日期", name: "pubDate", widget: "datetime", format: "YYYY-MM-DD", date_format: "YYYY-MM-DD", time_format: false }
      - { label: "更新日期（可选）", name: "updatedDate", widget: "datetime", format: "YYYY-MM-DD", date_format: "YYYY-MM-DD", time_format: false, required: false }
      - { label: "标签", name: "tags", widget: "list", default: [] }
      - { label: "翻译关联键（中英共用同一个值）", name: "translationKey", widget: "string", required: false }
      - { label: "正文", name: "body", widget: "markdown" }

  - name: "blog-en"
    label: "Blog · English"
    folder: "src/content/blog/en"
    create: true
    delete: true
    extension: md
    format: frontmatter
    slug: "{{slug}}"
    editor:
      preview: false
    fields:
      - { label: "Title", name: "title", widget: "string" }
      - { label: "Description", name: "description", widget: "text" }
      - { label: "Publish date", name: "pubDate", widget: "datetime", format: "YYYY-MM-DD", date_format: "YYYY-MM-DD", time_format: false }
      - { label: "Updated date (optional)", name: "updatedDate", widget: "datetime", format: "YYYY-MM-DD", date_format: "YYYY-MM-DD", time_format: false, required: false }
      - { label: "Tags", name: "tags", widget: "list", default: [] }
      - { label: "Translation key (same value as zh)", name: "translationKey", widget: "string", required: false }
      - { label: "Body", name: "body", widget: "markdown" }
```

要点：

- **双 collection**：路由按目录前缀识别语言（`zh/` → 无前缀 URL，`en/` → `/en/`），所以中英各建一个 collection 指向对应目录，CMS 写文件的位置天然正确。
- **`extension: md`**：CMS 新建文章保存为 `.md`。当前内容无 MDX 特性，Astro 的 `**/*.{md,mdx}` 两种扩展名都能渲染；既有 `.mdx` 文章保持 VSCode 维护（见 2.4）。
- **`pubDate` 用 `format: "YYYY-MM-DD"`**：与现有 frontmatter 风格一致，`z.coerce.date()` 可直接解析。
- **不启用 CMS 图片上传**：图片继续 PicGo → COS → 外链，编辑器里直接粘贴链接。

### 2.2 GitHub 认证：Personal Access Token（无需 OAuth App，约 3 分钟）

[官方文档](https://sveltiacms.app/en/docs/backends/github)明确：单用户/小团队场景用 PAT 最简，**不需要创建 OAuth App、不需要改配置**（OAuth 授权码流程仅多人协作才需要，且要额外部署 Cloudflare Worker 认证服务）。

1. 打开 [GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)](https://github.com/settings/tokens) → **Generate new token (classic)**
2. 勾选权限：**`repo`**（完整仓库读写，CMS 提交文章需要）；有效期自选（建议 90 天）
3. 生成后复制 token（**只显示一次**，妥善保存）
4. 打开 `https://fartmonarch.xyz/admin/` → 点 **Sign in with Token** → 粘贴 token
5. Token 只保存在浏览器 local storage，不落代码、不上服务器；疑似泄露时到 GitHub 设置 revoke 重建即可

### 2.3 本地验证清单

1. `npm run dev`，打开 `http://localhost:4321/admin/`
2. 点 **Sign in with Token** → 粘贴 PAT → 进入后台
3. 确认左侧出现 `blog-zh`、`blog-en` 两个集合
   - 若当前 Sveltia 版本能识别 `.mdx`，列表里会出现既有 `hello-world` 文章；否则列表为空是预期行为（CMS 只管 `.md` 新文章）
4. 新建一篇测试文章（blog-zh）：
   - 填标题/描述/日期/标签，正文写几行 Markdown
   - 保存 → 自动 commit + push 到 `main`
5. `git log` 确认 CMS 产生独立 commit；检查新文件 `src/content/blog/zh/<slug>.md` 的 frontmatter 与 schema 一致
6. 若登录或列表异常：见 2.4 风险表

### 2.4 风险与对策

| 风险 | 现象 | 对策 |
|---|---|---|
| Sveltia 不识别 `.mdx`（[Issue #79](https://github.com/sveltia/sveltia-cms/issues/79)，0.8.4 时代 bug，**已关闭**） | 文件列表里看不到既有 .mdx | 本方案用 `extension: md`，新文章走 `.md` 不受影响；既有 `hello-world.mdx` 保持 VSCode 维护。若希望 CMS 统一管理，可把两处 `.mdx` 转成 `.md` 后改 `extension: md` 即可全覆盖 |
| 新建文章 slug 与既有文件重名 | 路由重复 / 构建报错 | 新建时用英文短横线命名，避开既有文件名 |
| PAT 泄露 | 他人可修改仓库内容 | Token 只在浏览器本地；疑似泄露到 GitHub 设置 revoke 并重建 |
| frontmatter 不符合 schema | Vercel 构建失败（红） | 典型原因：**CMS 保存时会把空的可选字段写成 `''`**（如 `updatedDate: ''`），zod 4 会拒绝。已在 `content.config.ts` 用 `z.preprocess` 把空串转 `undefined` 根治，正常情况不会再触发；若仍报错，按报错提示修对应字段 |
| `/admin` 公网可访问 | 任何人都能打开登录页 | 个人博客可接受（无账号无法提交）；如需加固见附录一 |
| 双语言 `translationKey` 靠人工一致 | 中英文章可能失联 | 写作流程固定：先建中文 → 再建英文并复制同一个 translationKey（见 2.5） |

### 2.5 日常写作流程

- **快速发中文文章**：打开 `https://fartmonarch.xyz/admin/` → blog-zh → New → 填字段 → 正文图片用 COS 外链 `![](https://fartmonarch-cos-1344165548.cos.ap-shanghai.myqcloud.com/img/xxx.webp)` → Publish
- **配套英文版**：blog-en → New → 标题/正文翻译 → **translationKey 填与中文相同的值**
- **修改已有文章**：编辑保存 → 有实质更新记得填 `updatedDate` → Vercel 几十秒后自动上线
- **临时小改 / 手机**：GitHub 仓库按 `.` 键进 github.dev 直接改，或 GitHub 网页编辑
- **深度写作**：继续 VSCode（方案 A），现有 PicGo 图床流程不变

### 2.6 线上部署验证

1. 提交 admin 三件套 → push → Vercel 构建成功
2. 打开 `https://fartmonarch.xyz/admin/` 用 PAT 登录 → 发一篇真实测试文章 → 确认线上出现
3. 第五节验收清单全过即完成 P1

## 三、P2：Obsidian 方案（暂缓，附录）

> 决策依据：当前偶尔用 Obsidian；本地深度写作已由 VSCode + PicGo 覆盖，故**先不做**。若未来 Obsidian 成为主力笔记工具，按此步骤实施。

### 3.1 总体链路

```
Obsidian 编辑 → Obsidian Git 插件自动 push → fartmonarch/blog-content 仓库
                                                ↓（仓库内 GitHub Actions）
                                        Vercel Deploy Hook POST
                                                ↓
                          Vercel 重新构建：fetch-content.sh 拉取 → astro build
```

### 3.2 步骤

1. **建内容仓库**：GitHub 新建 `fartmonarch/blog-content`（可 private），结构：
   ```
   blog-content/
   ├── zh/*.md
   ├── en/*.md
   └── images/（可选，Obsidian 粘贴的图片）
   ```
2. **Obsidian 配置**：vault 指向本地 clone；安装 [obsidian-git](https://github.com/Vinzent03/obsidian-git)，`Vault backup interval` 设 **30+ 分钟**（避免频繁触发 Vercel 构建，消耗 [Hobby 构建配额](https://vercel.com/docs/plans/hobby)）
3. **项目接入**：
   - `scripts/fetch-content.sh`：
     ```bash
     #!/bin/bash
     set -e
     CONTENT_REPO="https://github.com/fartmonarch/blog-content.git"
     CONTENT_DIR="src/content/blog-external"
     if [ -d "$CONTENT_DIR/.git" ]; then
       git -C "$CONTENT_DIR" pull --ff-only origin main
     else
       git clone --depth 1 "$CONTENT_REPO" "$CONTENT_DIR"
     fi
     ```
   - `package.json`：`"build": "bash scripts/fetch-content.sh && astro build"`
   - **内容合并（两种做法二选一）**：
     - **做法 1（零改路由，推荐尝试）**：自定义 loader 把两个 glob 合并进同一个 `blog` collection：
       ```ts
       const localBlog = glob({ pattern: "**/*.{md,mdx}", base: "./src/content/blog" });
       const externalBlog = glob({ pattern: "**/*.{md,mdx}", base: "./src/content/blog-external" });
       const blog = defineCollection({
         loader: async (options) => {
           await Promise.all([localBlog.load(options), externalBlog.load(options)]);
         },
         schema: blogSchema,
       });
       ```
       ⚠️ 实施时验证：两个 glob 写入同一 store 的 id 冲突行为（id 是相对各自 base 的路径，同名文件会撞）。对策：外部仓库文章命名不与本地重名，或加载后改写 id 加前缀。
     - **做法 2（更稳妥）**：保留 `blog`，另加 `blogExternal` collection，新建 `src/lib/posts.ts` 的 `getAllPosts()` 合并两者，把 6 个路由文件（index / archive / tags / tags/[tag] / blog/[slug] / rss）里的 `getCollection("blog")` 换成 `getAllPosts()`（每处 1 行）。
4. **触发构建**：
   - Vercel Dashboard → 项目 → Settings → Git → Deploy Hooks → 创建 `content-update` → 复制 URL
   - `blog-content` 仓库加 `.github/workflows/trigger-deploy.yml`：
     ```yaml
     name: Trigger Vercel Deploy
     on:
       push:
         branches: [main]
     jobs:
       deploy:
         runs-on: ubuntu-latest
         steps:
           - run: curl -X POST "${{ secrets.VERCEL_DEPLOY_HOOK }}"
     ```
   - 仓库 Settings → Secrets and variables → Actions → 新增 `VERCEL_DEPLOY_HOOK`
5. **与 P1 共存**：VSCode / CMS / Obsidian 三条路写的内容最终在同一构建里合并，互不冲突。

### 3.3 P2 风险

- 5 个独立环节串联（插件 → 内容仓库 → fetch 脚本 → Deploy Hook → Actions），任一静默失败都表现为"博客没更新"，排查链路长
- 自动 push 频率 × Vercel Hobby 构建配额（见 [Vercel Hobby 文档](https://vercel.com/docs/plans/hobby)）
- Obsidian Git 移动端同步不稳定，手机场景仍靠方案 C / D
- 双语言结构同样适用：vault 内建 `zh/`、`en/` 子目录，`translationKey` 手动维护
