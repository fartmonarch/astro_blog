# 项目展示功能手册

> **定位**：记录「项目展示」这个功能**怎么开发出来的**、内部细节、以及**怎么用**。
> **完成时间**：2026-09-14。
> **相关文档**：[《项目展示配置与使用指南.md》](./项目展示配置与使用指南.md)（只讲日常使用与字段维护的速查版）、[《Sveltia CMS 配置与使用指南.md》](./Sveltia CMS 配置与使用指南.md)（CMS 本体）、[《图片上传COS操作指南.md》](./图片上传COS操作指南.md)（图床）。
>
> **一句话**：把「我发布过的仓库/工程」做成卡片展示——首页放一个项目模块，导航栏一个 `/projects/` 页面，内容在 `/admin/` 里增删改。

## 一、需求与最终形态

原始需求：展示 GitHub / Gitee / npm 上发布的项目仓库，首页加一个像归档一样的模块展示最近的项目，导航栏加一个项目页，页内每个项目可增删改、卡片化展示，卡片包含项目名称、项目链接、技术栈标签、项目简介。

需求确认过程中定下的几条（都影响实现）：

| 问题 | 结论 |
|---|---|
| 卡片点击进详情页吗？ | 不进。**不做详情页**，卡片本身就是全部信息；卡片本体不是链接 |
| 链接怎么给？ | **三个独立字段**：上线地址、源码仓库、npm 包地址，各自判空、填了才显示 |
| 星标/下载量这类实时数据？ | **不抓取**，纯手填、甚至不展示数字 |
| 技术栈怎么填？ | **不设白名单**，一个文本框用逗号分隔（`React, JSON, Viewer, 阮周刊`），构建时切成标签 |
| 增删改入口？ | 复用现有 `/admin/`（Sveltia CMS），新增一个「项目」集合 |
| 图标尺寸？ | 不要通栏封面图，要**像头像一样的小图标**；**正方形、无边框、底色 = 卡片底色**，方形/圆形 logo 都能正常展示 |
| 首页放哪些项目？ | **只放勾了「精选」的**；不勾精选的只在 `/projects/` 页面里出现。一条精选都没有时首页模块整体隐藏 |
| 卡片上放哪些信息？ | 图标、名称 + 精选徽章 + 状态徽章、平台图标、简介、技术栈、三个链接入口 |

最终形态：

| 位置 | 内容 |
|---|---|
| 导航栏 | 「项目」在首页和归档之间 → `/projects/` |
| 首页 | 「项目」模块：**只放精选项目**，最多 `PROJECTS_ON_HOME` 条，一行两个，底部「全部项目 →」 |
| `/projects/` | 全部项目，一行两个卡片（**不筛选、不分页**） |

## 三、数据流

```
/admin/ 填表 ──Publish──► src/content/projects/*.md（frontmatter + 可选正文）
                                    │
            markdownFiles() loader  │  解析 frontmatter、渲染正文、写进 DataStore
                                    ▼
                        project 集合（zod schema 校验 + 归一）
                                    │
                    getCollection("project")
                          ┌─────────┴─────────┐
                          ▼                   ▼
              pages/index.astro      pages/projects/index.astro
                          └─────────┬─────────┘
                                    ▼
                          ProjectCard.astro
```

「增删改」没有任何后端：CMS 拿着 GitHub Token 直接读写仓库里的 `.md`，提交触发 Vercel 重新构建。**没有数据库、没有 API 路由、不需要 SSR。**

### 一个项目的 frontmatter 长什么样

```yaml
---
title: 沫之白的小窝 # 卡片标题；也用作文件名
description: 你现在看到的这个博客…… # 卡片简介，超 3 行会被截断
status: 维护中 # 维护中 / 开发中 / 已归档，卡片上的状态徽章
platforms: [github] # github / gitee / npm，决定显示哪些平台图标
featured: true # 精选 → 卡片上出现「精选」徽章，并且会进首页
techStack: Astro, TypeScript, Sveltia CMS, Vercel # 逗号分隔，构建时切成标签
cover: "" # 图标 URL，留空显示标题首字
links:
  live: https://fartmonarch.xyz
  repo: https://github.com/fartmonarch/astro_blog
  npm: ""
---
正文不展示（这个集合没有详情页），只当备注用。
```

## 四、内部实现细节（开发时踩到的点）

### 4.1 loader 换成了自研版本（解决 `require is not defined`）

**这是这次最麻烦的一个问题，值得单独记。**

**症状**：`astro build` / `astro sync` 直接失败：

```
[GenerateContentTypesError] astro sync failed: require is not defined
    at eval (node_modules/picomatch/index.js:6:14)
    at ModuleRunner.directRequest (vite/dist/node/module-runner.js:1263)
```

`astro dev` **完全正常**（开发服务器不走同一条代码路径），所以一开始根本发现不了。

**排查过程**（结论都验证过）：

1. 与本次功能无关：把新增文件全部移走、`src/` 恢复到 `HEAD`，照样失败。
2. 依赖链是 `astro/loaders` 的 `glob()` → `tinyglobby` → `picomatch`（纯 CJS）。
3. 打桩 Vite 的 `ESModulesEvaluator.runInlinedModule` 抓到真凶：模块运行器把 **picomatch 的未转换源码** 直接交给求值器执行（`'use strict'; const pico = require('./lib/picomatch')`），而求值器用 `new AsyncFunction(...)` 执行、作用域里没有 `require`。
4. 也就是说 Vite 的 `optimizedDepsPlugin.load()` 把 `/node_modules/picomatch/index.js` 当成"已优化依赖文件"直接读盘返回，**跳过了 CJS → ESM 转换**。
5. 这是个依赖方的问题：`ssr.external` / `ssr.noExternal` / `optimizeDeps.exclude` / `optimizeDeps.force` / 别名 / 自定义 `resolveId` 外部化插件，**全部无效**；Vite 8.2.0 和 8.3.0 表现一致。

**修法**：绕开触发点，不再让内容配置依赖 `tinyglobby`。把三个集合的

```ts
loader: glob({ pattern: "**/*.{md,mdx}", base: "./src/content/blog" })
```

换成 `src/content.config.ts` 里的 `markdownFiles("./src/content/blog")`：只依赖 `node:fs` / `node:path` / `js-yaml`，职责与 `glob()` 相同（遍历目录 → 解析 frontmatter → `parseData` 校验 → `renderMarkdown` 渲染 → `store.set`）。

验证结果：`astro sync` 与 `npm run build` 全绿（31 个页面），博客正文、标题锚点、正文图片、TOC 全部与改动前一致。

**这个替换的代价（要记住）**：

- `.mdx` 里的 JSX / import **不会被处理**——它走的是同一套 Markdown 渲染。当前仓库没有 `.mdx` 内容，所以不影响；将来要用 mdx，得先解决 Vite 那个 bug 再换回 `glob()`。
- 依赖了 loader 的 `parseData` / `renderMarkdown` / `generateDigest` 这几个公开 API（`astro/loaders` 导出的 `LoaderContext` 类型里有），没有碰任何内部实现。
- 每次 load 都 `store.clear()` 重建（`glob()` 是用 digest 做增量）。18 篇博客的量级，构建耗时没有可感差异。**也因此开发时热更新正常**（`watcher.add(root)` 已在 loader 里调用）。

想换回官方 loader：把三处 `loader:` 改回 `glob({...})` 即可，代价是构建重新踩坑。

#### 4.1.1 开发模式的内容热更新（踩过一次的坑）

自研 loader 一开始只写了 `watcher.add(root)`，**没有挂 `change`/`add`/`unlink` 监听**。结果是：

- 改一个项目的 `status`、加一个新项目，**开发服务器完全不知道**，页面继续显示内容 store 里的旧值（实测：文件写着 `status: 已归档`，页面显示 `维护中`／`开发中`，怎么刷新都没用）；
- 只有**改内容配置本身、或重启 dev server**，才会触发整表重建。

这类"数据和显示对不上"的现象**极容易误判成代码 bug**。现在按 Astro 官方 `glob()` 的做法补齐了三件事：

```ts
// 1. 每个集合只处理自己目录下的文件（全局只有一个 watcher，三个集合共享）
const belongsHere = (file) => {
  const relative = path.relative(root, file);
  return relative !== "" && !relative.startsWith("..") && !path.isAbsolute(relative)
    && CONTENT_EXTENSIONS.includes(path.extname(relative));
};
// 2. change / add / unlink 都要听：改文件、新建文件、删文件
// 3. 换监听前先摘掉上一轮的 handler（WeakMap 记录），避免重复处理同一次事件
```

要点：

- **必须做 `belongsHere` 判断**。三个集合共挂同一个 Vite watcher，少了这层判断，博文的 loader 会去解析 `projects/` 下的文件，直接报 `data does not match collection schema`。
- 单文件的解析失败只 `logger.error`，不让整个 dev server 挂掉。
- 重建时用 `store.clear()` 整表刷新（`glob()` 用 digest 做增量），18 篇的量级耗时无感。

> **如果以后还遇到"文件改了但页面没变"**：先别怀疑代码，用 `npx astro dev stop && npx astro dev` 重启一次。本机（Windows + Node 26）上 Vite 的文件监听有时不推事件，重启是确定有效的办法——构建（`npm run build`）永远直接读盘，所以线上不会受影响。

#### 4.1.2 首页最多 4 张卡片是怎么落地的

需求里明确要求"首页最多展示 4 个项目卡片"，实现集中在 `src/pages/index.astro` 一处：

```ts
const featuredProjects = allProjects.filter((p) => p.data.featured);
featuredProjects.sort((a, b) => a.data.title.localeCompare(b.data.title, "zh-CN"));
const homeProjects = featuredProjects.slice(0, PROJECTS_ON_HOME);   // 唯一的截断点
```

模板里只渲染 `homeProjects`，**不再做任何二次截断**，所以"最多 4 个"只有一个出口，改 `src/config.ts` 的 `PROJECTS_ON_HOME` 即可。

实测（临时建 5 个精选 + 1 个非精选共 9 个项目）：首页渲染 4 张卡片，`/projects/` 渲染 9 张，非精选项目不出现在首页。

### 4.2 卡片图标：正方形、无边框、底色同卡片

图标位是 64px **正方形**、`border-radius: 8px`、**无 border**、`background: var(--card-bg)`、`object-fit: contain`。

四个刻意的选择：

| 选择 | 原因 |
|---|---|
| 不要 `border-radius: 50%` | 圆形会裁掉方形 logo 的四角 |
| 不要 `border` | 圆形透明底 PNG 加边框会变成"圆里套一个方框"；无边框最百搭 |
| 背景色 = `--card-bg`（**不是** `--dark`） | 图标和卡片完全融合，不会在卡片上留一个深色方块印子。有图时底色被图片盖住，等于"背景由上传的图片自己决定" |
| `contain` 而不是 `cover` | `cover` 会把长图/竖图裁掉两边；`contain` 只缩小、不裁切，是"上传任何形状都能正常展示"的关键 |

留空时退化成「项目名第一个字」+ 琥珀色字，做到**没有图也好看**。

> 顺带记一笔：`.icon` 曾经用过 `background: var(--dark)` + `linear-gradient(...)`。在深色主题下 `--dark` 是 `#010e54`、卡片本色是 `#00022b`，浅色主题下 `#ede4d3` vs `#f8e9cd`——都会在卡片上显出一块比卡片深/浅的方块，所以最终统一成 `var(--card-bg)`。

### 4.3 平台图标内联，不用 astro-icon

`BrandIcon.astro` 把 5 个图标的 path 直接写在组件里，`currentColor` 跟随主题：

- GitHub / Gitee / npm 取自 Simple Icons（CC0）；外链与仓库用的是 MDI 的 `open-in-new` / `source-repository`。
- 为什么不复用项目原有的 astro-icon：**它的本地图标集（`src/icons/`）在这个依赖环境下加载不出来**，页面报 `Unable to load the "local" icon set!`。它的 Vite 插件把异常整个吞掉（`catch {}`），虚拟模块于是导出 `undefined`。

所以 `src/icons/` 已经删掉，不要再往那里放图标。

### 4.4 技术栈：schema 层切分

`techStack` 在 frontmatter 里是**一个字符串**，切分发生在 zod 的 `preprocess` 里：

```ts
v.split(/[,，、]/) → trim → 丢空 → 去重 → string[]
```

于是卡片的**展示标签**直接拿到一份 `string[]`，不需要自己解析字符串。分隔符同时接受半角逗号、全角逗号和顿号。

> 这套切分原本还有个消费者：项目页顶部的「筛选按钮」也用同一份 `string[]` 汇总出按钮词表。**筛选功能后来整体删除了**（见 4.5），现在技术栈只做展示。

### 4.5 技术栈筛选功能已移除（含踩过的坑）

早期版本在 `/projects/` 顶部做了一排「按技术栈筛选」的按钮 + `?tech=` 直链还原。**后来整体删除**，原因：`?tech=LangChain` 这类链接实际不生效（页面静态渲染 + 内容缓存，筛选状态还原不可靠），而它要撑起的东西不少：

| 依赖链 | 说明 |
|---|---|
| `src/components/TechFilter.astro` | 按钮组组件（已删除文件） |
| `ProjectCard.astro` 的 `data-tech-stack` | 为了让筛选脚本做 DOM 过滤而透传的只读属性（已删） |
| 页面底部一段客户端脚本 | 读 `?tech=` → 切换卡片 `hidden` → `replaceState` 写回地址栏（已删） |
| `#filter-empty` 提示元素 + `.tech-filters`/`.filter-btn` 样式 | 空结果提示与按钮样式（已删） |

现在 `/projects/` 就是一个静态列表：**永远列全部项目**，`?tech=xxx` 被完全忽略（不会过滤、也不会报错，页面照常渲染全部卡片）。

> 这段历史值得留着的原因：它踩过两个和 Astro 有关的坑，将来若再写客户端脚本会重复遇到——
>
> 1. `<script is:inline>` 的 IIFE 用 `var` 会撞 eslint 的 `no-var`；改成 `let/const` 后又发现 **`is:inline` 的脚本不经过 Vite 处理、源码原样进 HTML，但 eslint/prettier 仍然按 JS 解析它**。当时改用普通 `<script>`（Astro 会打包）。
> 2. 客户端脚本**不能写在 JSX 表达式里**（`{cond && <script>…</script>}`）——`prettier-plugin-astro` 对"表达式里的 `<script>`"会报 `SyntaxError: Unexpected token`。当时把脚本移到 `<BaseLayout>` 之外的模板顶层，并在第一行做空值 return。

### 4.6 组件样式作用域的两个约束

- 组件内的 `<svg>` 是子组件渲染的，父组件想改它的尺寸要用 `:global(svg)`（`BrandIcon` 自身用 `1em` 尺寸，父级改 `font-size` 即可）。
- 卡片要能在父组件里被栅格控制，所以 `ProjectCard` 自身是 `height: 100%`、**不带栅格**；栅格写在两个页面里。

> 还有一条曾经踩到的：**页面级选择器管不到子组件里渲染出来的元素**（Astro 会给两个文件不同的 `data-astro-cid`）。当时筛选按钮被抽成独立组件、用 `:global(...)` 集中样式；现在筛选删了，这条约束对剩余代码不再有影响，但换任何"页面里写选择器、组件里渲染元素"的写法都要记得它。

### 4.7 排序，以及首页的精选门槛

```
精选优先 → 项目名称（localeCompare "zh-CN"）
```

不用日期、不用文件系统返回顺序。原因：Sveltia 目前**不支持文件夹集合的手动拖拽排序**（[sveltia/sveltia-cms#214](https://github.com/sveltia/sveltia-cms/issues/214)），没有可靠的"用户自定义顺序"可读。

首页的取数与项目页不同：

```ts
// pages/projects/index.astro —— 全部项目
projects.sort(精选优先 → 名称)

// pages/index.astro —— 先按精选过滤，再排序、截断
const featuredProjects = allProjects
  .filter((project) => project.data.featured)
  .sort((a, b) => a.data.title.localeCompare(b.data.title, "zh-CN"))
  .slice(0, PROJECTS_ON_HOME);
```

- **`featured` 是上首页的门槛**：没勾精选的项目只会出现在 `/projects/` 里，不会进首页。
- 精选项目之间按名称排序（都是精选，第一优先级已经相等），所以首页与项目页里这些项目的相对顺序一致。
- **一条精选都没有 → 首页模块整体隐藏**（模板里是 `featuredProjects.length > 0 && (...)`），不会留一个空标题。
- 卡片上 `featured: true` 会渲染一个实色的「精选」徽章（`badge-featured`），状态用描边徽章（`badge-status`），两个并排。

> 走过一次弯路，记在这里避免再犯：曾经把「精选」理解成"只影响排序、不影响是否展示"（改成"不勾也会上首页"），又把状态字段误当成"用户不要的分类标签"删掉了。**正确的语义是：精选 = 首页准入门槛 + 卡片徽章；状态 = 保留、卡片徽章。**

## 五、怎么用

### 5.1 加一个项目

1. 打开 <https://www.fartmonarch.xyz/admin/>，登录（GitHub Token，见《Sveltia CMS 配置与使用指南.md》3.1）
2. 左侧 **项目** → 右上 **New 项目**
3. 填字段（见 5.2）→ 右上 **Publish** → 自动 commit → Vercel 自动构建上线

条目文件落在 `src/content/projects/<项目名称>.md`。**没有 Slug 输入框**，文件名由「项目名称」自动生成；中文文件名没关系（项目没有独立 URL）。

### 5.2 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | 是 | 卡片标题，也是文件名 |
| 项目简介 | 是 | 卡片上一段话，超过 3 行会被截断（`-webkit-line-clamp: 3`） |
| 状态 | 是 | `维护中` / `开发中` / `已归档`，卡片上项目名旁边的徽章 |
| 平台 | 否 | `github` / `gitee` / `npm` 多选，选中几个显示几个图标 |
| 精选 | 否 | **上首页的门槛**：勾了才进首页，并且在卡片上显示「精选」徽章。不勾只在 `/projects/` 里出现 |
| 技术栈标签 | 否 | 一个文本框，逗号分隔：`React, JSON, Viewer, 阮周刊`（**只做展示，没有筛选功能**） |
| 封面图 URL | 否 | 项目图标，正方形/圆形都行；留空显示项目名首字 |
| 项目链接 | 否 | 折叠分组，含 **上线地址 / 源码仓库 / npm 包地址** 三个独立字段 |
| 备注（正文） | 否 | 卡片不展示，留作备注 |

**三个链接互相独立**：填哪个显示哪个，全空则整块不显示。

### 5.3 技术栈标签

- 分隔符：半角逗号 `,`、全角逗号 `，`、顿号 `、` 都行
- 自动去首尾空格、丢空段、去重：`React, , JSON，Vue、React` → `React` / `JSON` / `Vue`
- `/projects/` 顶部的筛选按钮**已移除**：页面永远列全部项目，加新技术栈不用改任何配置，也不会多出按钮（见 4.5）

### 5.4 项目图标

- 填了 URL：正方形展示、`contain` 缩放，**任何形状的图都不会被裁切**
- 图标底色就是卡片底色，所以和卡片完全融合；有图时背景由图片自己决定
- 留空：显示项目名第一个字
- 图要先用 PicGo 传到 COS 拿外链再填（CMS 内没有上传按钮）
- 想改图标大小：改 `ProjectCard.astro` 里 `.icon` 的 `--icon-size`（默认 `64px`）

### 5.5 精选、首页与排序

- 首页只放**精选**项目，最多 `src/config.ts` 的 `PROJECTS_ON_HOME` 条（默认 4）
- 顺序：精选优先 → 名称
- **一条精选都没有 → 首页整个模块隐藏**（想让它出现就至少勾一个精选）
- `/projects/` 永远展示全部项目，不受精选影响
- 集合里一条项目都没有时，首页模块隐藏、`/projects/` 显示引导文案，都不会报错

### 5.6 删 / 改

- 改：`/admin/` → 项目 → 点条目 → 改 → Publish
- 删：`/admin/` → 项目 → 条目右侧 `⋮` → Delete
- 或者直接在编辑器里改/删 `src/content/projects/*.md`

### 5.7 让某个项目上首页

两种方式，效果一样：

1. `/admin/` → 项目 → 点条目 → 打开「精选」→ Publish
2. 直接改 `src/content/projects/<文件>.md` 的 `featured: true`

## 七、排错

| 现象 | 原因 / 处理 |
|---|---|
| 构建报 `require is not defined`（picomatch） | 有人把 `markdownFiles()` 换回 `glob()` 了，或者依赖变了。见 4.1 |
| 构建报 `Invalid enum value` 并点名某个值 | 状态或平台拼写与代码里的枚举不一致，照报错里的合法值改 |
| CMS 里存得进、构建失败 | `config.yml` 加了字段但 `content.config.ts` 没同步 |
| 技术栈没切开 | 分隔符用了别的符号（如分号）。只认 `,` `，` `、` |
| 技术栈标签点了没反应 / `?tech=` 无效果 | 筛选功能已整体移除（见 4.5），页面永远列全部项目 |
| 图标显示不完整/被裁 | 有人把 `.icon img` 的 `object-fit` 改回 `cover` 了，应该是 `contain` |
| 图标外多出一块方块/圆框 | 给 `.icon` 加了 `border`，或把背景改成了 `--dark`。应该无 border + `background: var(--card-bg)` |
| 首页看不到某个项目 | 它没勾「精选」。见 4.7 / 5.7 |
| 首页「项目」模块整块不见了 | 一条精选都没有，模板会隐藏整个模块 |
| 首页卡片超过 4 张 | 检查 `src/config.ts` 的 `PROJECTS_ON_HOME`，以及 `index.astro` 里 `homeProjects` 的 `slice` 有没有被去掉 |
| 改了 md 但开发页面不变（状态/内容对不上） | 内容 store 是旧的。先 `npx astro dev stop && npx astro dev` 重启；见 4.1.1。`npm run build` 不受影响 |
| 控制台报 `Unable to load the "local" icon set!` | astro-icon 本地图标集坏了（与卡片无关）。卡片图标已不走它；`Profile.astro` 用的 `mdi:` 图标不受影响 |
| 技术栈标签点了没反应 / `?tech=` 无效果 | 筛选功能已整体移除（见 4.5），页面永远列全部项目，这个参数被忽略 |
| 部署后没变化 | Vercel 构建是否成功；CMS Publish 是否真的 commit 到了 `main` |

## 九、已知限制

| 限制 | 说明 |
|---|---|
| 没有手动拖拽排序 | Sveltia 不支持文件夹集合手动排序。想调顺序只能靠「精选」（代价是它同时会进首页） |
| 精选 = 上首页门槛 | 所以"只想排序、不想上首页"做不到：想让某个项目排在前面，它就会进首页 |
| 不做详情页 | 卡片是唯一承载信息的地方，想写长文只能放简介（会被截 3 行） |
| 不抓实时数据 | 星标数、下载量、最后更新时间都没有，纯手填 |
| `.mdx` 只按 Markdown 渲染 | 自研 loader 的代价；当前仓库无 `.mdx` 内容 |
| 不做 i18n | 站点本身已移除中英双语 |
| 外链图无兜底 | 图标是 `<img src>` 直连 COS 外链，链接失效就是裂图（有 `alt` 与固定尺寸，布局不会塌） |
