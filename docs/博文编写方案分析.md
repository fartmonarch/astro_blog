# 博文编写方案分析

目标：多种写博客方式并存，统一数据源，适配 Vercel 部署。

## Vercel 部署约束

| 约束项 | 限制 |
|---|---|
| 无持久服务器 | 不能运行后台进程监听文件变更 |
| Serverless 函数 | Hobby 版 10s 超时、Pro 版 60s |
| 构建时间 | 最长 45 分钟 |
| 文件系统 | 只读，无法运行时写入（`/tmp` 除外） |
| Git Submodule | 构建时支持 checkout |
| Deploy Hook | 支持，可通过 HTTP POST 触发重新部署 |

核心思路：所有写入路径最终都落到 **GitHub 仓库**，由 Vercel 的 Git 集成自动检测变更并重新构建。

---

## 方案一览

| # | 方案 | 编辑器 | 写入方式 | 复杂度 | 推荐 |
|---|------|--------|----------|--------|------|
| A | VSCode + Git Push | VSCode | 直接在项目中编辑 | 低 | ⭐⭐ |
| B | Obsidian + Git Sync | Obsidian | Obsidian Git 插件提交到独立仓库 | 中 | ⭐⭐⭐⭐⭐ |
| C | Web CMS（Decap / Tina） | 浏览器 | Git-based CMS 提交到仓库 | 中 | ⭐⭐⭐⭐ |
| D | GitHub 网页编辑 | 浏览器（GitHub.dev） | 在线编辑直接提交 | 极低 | ⭐⭐⭐ |
| E | Headless CMS（Contentful 等） | 浏览器 | API 拉取 | 高 | ⭐⭐ |
| F | 旧博客方案（自建 Web CMS） | 浏览器 | 前端调用 GitHub API | 极高 | ⭐ |

---

## 方案 A：VSCode + Git Push（当前方案）

```
VSCode 编辑 → git commit → git push → Vercel 自动检测 → 构建部署
```

当前的工作方式。直接在项目 `src/content/blog/` 下创建 `.md`/`.mdx` 文件。

- ✅ 零额外配置，已经在用
- ✅ 完全离线可用
- ✅ 图片可直接用图床链接
- ❌ 必须在能装 Git 的设备上操作
- ❌ 移动端无法写博客

---

## 方案 B：Obsidian + Git Sync + Vercel Deploy Hook（推荐）

```
Obsidian 编辑 → Obsidian Git 插件自动 push → 独立内容仓库
                                                    ↓
                                        Vercel Deploy Hook
                                                    ↓
                                        Astro 构建时 Git Clone 内容仓库
```

### 架构设计

```
fartmonarch/blog-content/          ← Obsidian 同步到这个独立仓库
├── zh/
│   ├── vue3-directives.md
│   └── new-post.md
├── en/
│   └── hello-world.md
└── images/                        ← Obsidian 粘贴的图片也存这里（可选）
    └── xxx.webp

fartmonarch/astro-blog/            ← Astro 项目本身
├── src/
│   ├── content.config.ts          ← 改为从外部仓库加载
│   └── ...
├── scripts/
│   └── fetch-content.sh           ← 构建时拉取内容仓库
└── package.json                   ← build 命令先执行 fetch-content
```

### 实施步骤

**第一步：创建独立内容仓库**

在 GitHub 创建 `fartmonarch/blog-content` 仓库，结构如上。

**第二步：Obsidian 配置**

1. 打开 Obsidian，将 vault 目录设置为本地 clone 的 `blog-content` 仓库
2. 安装 [Obsidian Git](https://github.com/Vinzent03/obsidian-git) 插件
3. 配置自动同步：

```
Vault backup interval: 10（每 10 分钟自动 commit + push）
Auto pull on startup: 开启
```

Obsidian 每次编辑后就自动推到 GitHub。

**第三步：Astro 项目集成**

`scripts/fetch-content.sh`：

```bash
#!/bin/bash
CONTENT_REPO="https://github.com/fartmonarch/blog-content.git"
CONTENT_DIR="src/content/blog-external"

if [ -d "$CONTENT_DIR/.git" ]; then
  cd "$CONTENT_DIR" && git pull origin main
else
  git clone --depth 1 "$CONTENT_REPO" "$CONTENT_DIR"
fi
```

`package.json` 修改：

```json
{
  "scripts": {
    "build": "bash scripts/fetch-content.sh && astro build"
  }
}
```

`content.config.ts` 添加第二个 loader：

```ts
const blogObsidian = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/blog-external/zh" }),
  schema: blogSchema,
});
```

**第四步：触发 Vercel 重新构建**

内容仓库变化时需要通知 Vercel 重建。有两种方式：

方式 A — GitHub Actions（在 `blog-content` 仓库）：

```yaml
# .github/workflows/trigger-deploy.yml
name: Trigger Vercel Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -X POST "${{ secrets.VERCEL_DEPLOY_HOOK }}"
```

方式 B — Vercel Deploy Hook 直接配置在 Obsidian Git 插件的 post-push hook 里。

### Vercel Deploy Hook 设置

1. Vercel Dashboard → 项目 → Settings → Git → Deploy Hooks
2. 创建 Hook，命名为 `content-update`
3. 得到 URL：`https://api.vercel.com/v1/integrations/deploy/xxx`
4. 将此 URL 填入 GitHub Actions 的 `VERCEL_DEPLOY_HOOK` secret

### 可行性评估

- ✅ Vercel 支持 Git Clone（构建阶段有网络访问）
- ✅ `--depth 1` 浅克隆，几秒完成，几乎不增加构建时间
- ✅ 图片可继续用 COS 图床链接，Obsidian 中写 `![](url)` 即可
- ✅ Obsidian 完全离线可用，联网后自动同步
- ✅ 和方案 A 共存：项目内 `src/content/blog/` 继续手动维护
- ⚠️ 构建频率取决于 Obsidian 同步频率，建议设 10-30 分钟间隔避免频繁构建

## 方案 C：Web CMS（Decap CMS / Sveltia CMS）

```
浏览器打开 /admin → 可视化编辑 → 提交到 GitHub → Vercel 自动构建
```

### Decap CMS（原 Netlify CMS）

- 纯 Git-based，所有内容存于仓库
- 通过 OAuth 直接提交到 GitHub（无需 GitHub App）
- Astro 官方有集成指南：[Decap CMS + Astro](https://docs.astro.build/en/guides/cms/decap-cms/)

配置示例（`public/admin/config.yml`）：

```yaml
backend:
  name: github
  repo: fartmonarch/astro-blog
  branch: main

media_folder: "public/images"
public_folder: "/images"

collections:
  - name: "blog"
    label: "博客"
    folder: "src/content/blog/zh"
    create: true
    fields:
      - { label: "标题", name: "title", widget: "string" }
      - { label: "描述", name: "description", widget: "text" }
      - { label: "日期", name: "pubDate", widget: "datetime" }
      - { label: "标签", name: "tags", widget: "list", default: [] }
      - { label: "正文", name: "body", widget: "markdown" }
```

### Sveltia CMS（Decap 的现代化替代）

- 比 Decap 更快、UI 更好
- 完全兼容 Decap 的 config.yml
- 单一 HTML 文件，无需构建步骤

### 可行性评估

- ✅ 可视化编辑，非技术人员也能用
- ✅ Git-based，和当前工作流兼容
- ✅ 支持图片上传（自动提交到仓库 or 可配置 COS）
- ⚠️ 需要 GitHub OAuth App 认证（一次性配置，5 分钟）
- ⚠️ Sveltia CMS 的单文件约 200KB，无运行时依赖
- ✅ 和方案 A、B 完全共存

## 方案 D：GitHub 网页编辑

```
浏览器打开 github.dev 或 github.com → 在线编辑 → 提交 → Vercel 自动构建
```

### 两种方式

| 方式 | URL | 体验 |
|------|-----|------|
| **GitHub.dev** | 在仓库页面按 `.` 键 | 完整 VSCode 体验在浏览器中 |
| **GitHub 网页** | 直接在仓库文件中点 Edit | 简单的文本编辑器 |

### GitHub.dev 功能

- VSCode 的 Web 版，支持语法高亮、Markdown 预览、Git 操作
- 安装 PicGo 插件不可用（Web 版无法运行本地 node 进程）
- 但可以直接粘贴 COS 图床链接

### 可行性评估

- ✅ 零配置，直接可用
- ✅ 任何有浏览器的设备都能写博客（包括 iPad、手机）
- ✅ 和所有方案共存
- ❌ 需要手动写 frontmatter，无可视化表单
- ❌ 图片需要手动处理（先上传 COS 再复制链接）

---

## 方案 E：Headless CMS（Contentful / Strapi / Sanity）

```
浏览器 CMS 后台 → 编辑内容 → API 发布 → Astro 构建时拉取 → 部署
```

### 工作方式

不在仓库存 md 文件，而是构建时通过 API 拉取内容：

```ts
// content.config.ts
const blog = defineCollection({
  loader: async () => {
    const entries = await fetch("https://cdn.contentful.com/...").then(r => r.json());
    return entries.map(e => ({ id: e.sys.id, rendered: { html: e.fields.body } }));
  },
});
```

### 可行性评估

- ✅ 专业内容管理，支持协作、审核、版本管理
- ❌ 对个人博客过度设计
- ❌ Contentful 免费版有 1M 次 API 调用限制
- ❌ 构建时 API 拉取增加构建时间
- ❌ Vercel ISR 有请求次数限制，无法频繁增量更新
- ❌ 脱离 Git，内容不在版本控制中（除非付费版）

---

## 方案 F：旧博客方案（自建 Web CMS + GitHub API）

```
网页编辑器 → GitHub App JWT 认证 → GitHub API 直接提交 → Vercel 构建
```

旧博客 `blog-public` 的做法。完全自建的前端 CMS。

### 可行性评估

- ✅ 完全自定义的编辑体验
- ❌ 开发量极大（认证、文件管理、图片上传、JWT 签名、AES 加密）
- ❌ 维护成本高
- ❌ 浏览器端暴露 GitHub App 私钥有安全隐患（即使加密也存在）
- 建议：用方案 C（Decap/Sveltia CMS）替代，它已经解决了所有这些问题

---

## 推荐组合

```
方案 B（Obsidian）+ 方案 A（VSCode）+ 方案 C（Sveltia CMS）+ 方案 D（GitHub 网页）
```

| 场景 | 用哪个 |
|------|--------|
| 日常深度写作、知识管理 | **Obsidian**（方案 B），本地编辑体验最好，自动同步 |
| 技术文章、需要代码高亮 | **VSCode**（方案 A），直接在项目里改，立即生效 |
| 快速发一篇、不想开编辑器 | **Sveltia CMS**（方案 C），浏览器打开 `/admin` 直接写 |
| 临时小改、手机/平板 | **GitHub 网页**（方案 D），按 `.` 键在线改 |

### 数据流统一

```
                    ┌─────────────────────────────┐
                    │     fartmonarch/astro-blog    │
                    │                              │
VSCode ─────────────┤  src/content/blog/           │
                    │  src/content/blog-external/   │◄── git clone ── fartmonarch/blog-content ◄── Obsidian Git
Sveltia CMS ────────┤  (直接提交到仓库)              │
GitHub Web ─────────┤  (直接编辑仓库文件)            │
                    │                              │
                    └──────────┬──────────────────┘
                               │
                         Vercel 构建部署
```

所有路径最终都落到同一个 GitHub 仓库，Vercel 检测到变更后自动构建。方案 B 的内容放在独立仓库，通过构建脚本拉取合并。其它方案直接操作 Astro 项目仓库。
