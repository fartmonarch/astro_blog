# 图床自动化方案

在本地写博客时，粘贴图片自动上传到图床并生成 Markdown 链接。当前图床为腾讯云 COS：`fartmonarch-cos-1344165548.cos.ap-shanghai.myqcloud.com`。

## 方案对比

| | 方案 1 GitHub 图床 | 方案 2 PicGo 桌面 | 方案 3 VSCode 插件 |
|---|---|---|---|
| 上手难度 | 高（需自建 CMS） | 低 | 极低 |
| 图片存储 | GitHub 仓库 | 腾讯云 COS | 腾讯云 COS |
| 体验 | 浏览器编辑器内置 | 截图→快捷键→上传 | 编辑器内粘贴即传 |
| 额外软件 | 浏览器 | PicGo 桌面端 | 无 |
| 推荐指数 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |

## 方案 1：GitHub 图床（旧博客方案）

旧博客 `blog-public` 的实际做法。核心思路：把图片通过 GitHub REST API 直接提交到仓库，利用仓库作为存储和分发。

### 技术架构

```mermaid
flowchart LR
    A[拖入图片] --> B[生成 local-image:id 占位符]
    B --> C[写 Markdown 内容]
    C --> D[点击发布]
    D --> E[计算文件 SHA256]
    E --> F[Base64 编码图片]
    F --> G[GitHub API: createBlob]
    G --> H[createTree]
    H --> I[createCommit]
    I --> J[updateRef]
    J --> K[替换占位符为真实 URL]
```

### 关键实现

**认证流程**（`src/lib/auth.ts`）：

1. 用户 GitHub App 私钥（PEM）经 AES-256 加密缓存在 `sessionStorage`
2. 发布时用 `jsrsasign` 签 RS256 JWT
3. JWT 交换 GitHub Installation Token
4. Token 缓存复用

**文件命名**（`src/lib/file-utils.ts`）：

```ts
// SHA256 前 16 位作为文件名，自动去重
function hashFileSHA256(file: File): string {
  // 返回 hash 的前 16 个十六进制字符
}
```

**Git 操作**（`src/lib/github-client.ts`）：

```ts
// 一套 Git Data API 完成原子提交
createBlob(content, encoding) → sha
createTree(baseTree, [{ path, mode, type, sha }]) → sha
createCommit(message, tree, parents) → sha
updateRef(ref, sha) → void
```

**占位符替换**（`src/app/write/services/push-blog.ts`）：

```
编辑时：  ![](local-image:abc123)
发布后：  ![](/blogs/vue3-directives/a1b2c3d4.webp)
```

### Config 文件

`src/consts.ts`：

```ts
const GITHUB_CONFIG = {
  owner: "fartmonarch",
  repo: "blog-public",
  branch: "main",
  appId: "3114648",
  path: "public/blogs",
};
```

### 优点

- 免费，无第三方存储依赖
- 图片和文章版本绑定，Git 历史可追溯
- 同 hash 文件自动去重，不浪费空间

### 缺点

- 需要 GitHub App 认证配置
- 代码量大（JWT 签名、AES 加密、Git Data API 全套封装）
- 仓库体积随图片增多持续增长
- 没有 CDN 加速，国内访问速度一般

## 方案 2：PicGo + 腾讯云 COS

PicGo 是开源图床管理客户端，结合腾讯云 COS 插件，截图或拖拽图片即可自动上传并返回 Markdown 链接。

### 安装步骤

1. 下载 [PicGo](https://molunerfinn.com/PicGo/)（Windows/macOS/Linux）
2. 打开 PicGo → 插件设置 → 搜索 `picgo-plugin-tencent-cos`（作者：Pika_TQL）→ 安装
3. 重启 PicGo

### COS 配置

在 PicGo → 图床设置 → 腾讯云 COS 中填入：

```
COS 版本：       v5
SecretId：       你的腾讯云 API SecretId
SecretKey：      你的腾讯云 API SecretKey
Bucket：         fartmonarch-cos-1344165548
AppId：          1344165548
Area：           ap-shanghai
存储路径：        img/
自定义域名：      https://fartmonarch-cos-1344165548.cos.ap-shanghai.myqcloud.com/img/
```

> SecretId / SecretKey 在 [腾讯云 API 密钥管理](https://console.cloud.tencent.com/cam/capi) 获取。建议使用子账号密钥，仅授予 COS 写入权限。

### 日常使用

| 操作 | 方法 |
|---|---|
| 截图上传 | 截图后按 `Ctrl+Shift+P`（可自定义快捷键）→ 链接自动写入剪贴板 |
| 拖拽上传 | 拖图片到 PicGo 窗口或任务栏图标 |
| 剪贴板上传 | PicGo → 上传区 → "点击上传"，或右键任务栏图标 → "从剪贴板上传" |
| 相册管理 | PicGo 主界面 → 相册 → 查看/复制/删除已上传的图片 |

### Markdown 链接格式

上传后剪贴板自动得到：

```markdown
![image](https://fartmonarch-cos-1344165548.cos.ap-shanghai.myqcloud.com/img/a1b2c3d4.webp)
```

在 `.md` 文件中直接 `Ctrl+V` 粘贴即可。

### 优点

- 开箱即用，无需写代码
- 支持多种图床（COS / OSS / GitHub / SM.MS / 七牛等）
- 有相册管理界面，方便浏览和删除历史图片
- 快捷键操作用起来很快

### 缺点

- 需要额外安装桌面软件
- 写博客和上传图片在两个窗口之间切换

## 方案 3：VSCode + PicGo 插件（推荐）

在 VSCode 内直接完成图片上传，不离开编辑器，粘贴即传。

### 安装

VSCode 扩展市场搜索 `PicGo`（作者：Spades-S）→ 安装。

### COS 配置

打开 VSCode `settings.json`，添加：

```json
{
  "picgo.picBed.uploader": "tcyun",
  "picgo.picBed.tcyun": {
    "secretId": "你的腾讯云 API SecretId",
    "secretKey": "你的腾讯云 API SecretKey",
    "bucket": "fartmonarch-cos-1344165548",
    "appId": "1344165548",
    "area": "ap-shanghai",
    "path": "img/",
    "customUrl": "https://fartmonarch-cos-1344165548.cos.ap-shanghai.myqcloud.com/img/"
  },
  "picgo.picBed.current": "tcyun"
}
```

> SecretId / SecretKey 同上，在 [腾讯云 API 密钥管理](https://console.cloud.tencent.com/cam/capi) 获取。

### 日常使用

| 操作 | 方法 | 快捷键 |
|---|---|---|
| 剪贴板上传 | 截图或复制图片后按快捷键 | `Ctrl+Alt+U`（Windows） |
| 文件选择上传 | 命令面板 → `PicGo: Upload Image from File Explorer` | — |
| 资源管理器上传 | 右键图片文件 → `上传图片` | — |
| 粘贴自动上传 | 在 `.md` 文件中粘贴图片时自动触发（需在设置中开启） | `Ctrl+V` |

### 粘贴自动上传配置（可选）

如果想做到在 md 文件中直接 `Ctrl+V` 粘贴图片就自动上传，追加设置：

```json
{
  "picgo.pasteAndUpload": true
}
```

### 优点

- **零切换**，写博客和上传图片在同一个 VSCode 窗口
- 粘贴即传，流程最简洁
- 不装额外软件
- 和方案 2 共用同一个 COS 桶，不冲突

### 缺点

- 无相册管理界面（查看历史图片需要去 COS 控制台或 PicGo 桌面端）
- 插件功能比桌面版 PicGo 精简

---

## 推荐组合

**方案 3 为主 + 方案 2 为辅**：

- 日常写博客用 VSCode 插件的粘贴即传（方案 3）
- 需要批量管理/清理历史图片时打开 PicGo 桌面端用相册功能（方案 2）
- 两者共用同一个 COS 存储桶，互不冲突
