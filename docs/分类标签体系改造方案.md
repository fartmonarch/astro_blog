# 分类/标签体系改造方案

> **日期**：2026-09-11
> **基线**：`daffccd`（上一轮"移除中英双语"提交）
> **状态**：**已实施完成**，改动已暂存未提交，验证记录见文末「九、实施结果与验证记录」
> **目标**：把"标签"拆成两种东西——只有少量受控的**分类**能生成页面、能点击跳转；其余**标签**退化为关键词展示，不可点击、不生成页面。同时引入**未分类**状态，让现有 12 篇文章和以后忘记填分类的文章都有合法归属，且随时可回填。

## 一、目标与成功标准

**成功标准**：

1. `/tags/`（分类索引页）只出现白名单分类 +「未分类」，不再出现一次性标签。
2. 文章详情页：分类渲染成可点链接；标签渲染成不可点的弱化文字。
3. 三种写法（VSCode / Sveltia CMS / GitHub.dev）都能**完全不填分类**就发布，落为「未分类」；之后都能回填。
4. `npm run build`、`npm run lint` 通过；12 篇现有文章**不用改 frontmatter** 即自动进入未分类。

### 改造前的现状（12 篇文章 / 16 个标签）

| 标签 | 文章数 | 标签 | 文章数 |
|---|---|---|---|
| 学习笔记 | **6** | AI学习、博客构造、计算机网络、ES6、入门、博客 | 各 1 |
| 总结 | **3** | 电脑问题、线下、实地、Nginx、后端技术 | 各 1 |
| | | 快捷键、开源、Vue | 各 1 |

16 个标签里 13 个只用过一次——一次性标签撑不起"分类"，却让每篇详情页挂着一排可点的假分类。另外 CMS 的「标签」字段没写 `required: false`，而 Sveltia/Decap 的字段 `required` **默认是 `true`**，所以写文章时被强制填标签。

## 二、概念模型（本次设计的核心）

| 概念 | frontmatter 字段 | 词表 | 有页面？ | 详情页可点？ |
|---|---|---|---|---|
| **分类** | `categories`（新增） | 受控，白名单 1~3 个 | ✅ `/tags/<分类>/` | ✅ |
| **标签** | `tags`（保留原字段名） | 自由文本，不限 | ❌ | ❌ 纯展示 |
| **未分类** | 不进 frontmatter | — | ✅ `/tags/未分类/`（虚拟页） | ✅（文章没有分类时显示该 chip） |

### 「未分类」为什么用"空值"而不是一个可选分类

用 **`categories` 缺失/为空数组**表示未分类，**不是**把"未分类"塞进白名单当一个可选分类。理由：

- 语义诚实——没填就是没填，不必为了"没分类"去勾一个假选项；
- 不会出现"同时勾了 `未分类` + `技术笔记`"这种脏状态；
- 白名单保持纯净，以后加分类不会和它混在一起。

「未分类」仍然有可访问的落地页 `/tags/未分类/`，所以这个状态是**可浏览、可点进去看**的，只是不占白名单名额。

## 三、改动清单（按子系统）

### 3.1 词表与 schema

**`src/config.ts`** —— 新增两个导出，作为分类词表的唯一代码来源：

```ts
// 文章分类（受控词表）：只有这里列出的词才会生成分类页面。
// 新增/改名分类要同步改两处：这里 + public/admin/config.yml 的 select options
export const CATEGORIES = ["技术笔记", "博客建设", "生活记录", "问题排查"] as const;

// 「未分类」是状态，不是分类：不进白名单，只用于路由和展示
export const UNCATEGORIZED = "未分类";
```

**`src/content.config.ts`** —— 加 `categories`，并把 `tags` 变成宽松可选：

```ts
import { CATEGORIES } from "./config";

// 同 optionalDate 的思路：Sveltia 可能把空值写成 ''（本项目已踩过 updatedDate 的坑），
// 这里把 ''/null/undefined 统一归一成 []，避免 zod 把空串当成数组类型错误
const stringArray = z.preprocess(
  (v) => (v === "" || v == null ? [] : v),
  z.array(z.string()).default([]),
);
const categoryArray = z.preprocess(
  (v) => (v === "" || v == null ? [] : v),
  z.array(z.enum(CATEGORIES)).max(3).default([]),
);
```

schema 改为：

```ts
    categories: categoryArray,   // 留空 = 未分类
    tags: stringArray,           // 仅展示
```

> 严格 enum 的副作用（可接受且是我们要的）：VSCode 里手写不在白名单的分类名 → **构建失败并直接报出非法值**，逼你从白名单选。

### 3.2 CMS 字段（`public/admin/config.yml`）

```yaml
      - { label: "分类", name: "categories", widget: "select", multiple: true, min: 0, max: 3, required: false, default: [], options: ["技术笔记", "博客建设", "生活记录", "问题排查"], hint: "留空 = 未分类，之后可以随时回来补" }
      - { label: "标签（仅展示，不参与分类）", name: "tags", widget: "list", default: [], required: false, hint: "只做关键词展示，不生成分类页面" }
```

要点：

- **`required: false` 是关键修复**：Sveltia/Decap 字段 `required` 默认 `true`（官方文档："Unless explicitly set to `false`, fields are required by default"），当前 `tags` 没写，所以才会被强制填写。
- 官方文档确认：多选 `select` + `required: false` 时，不选任何项 → 保存为空数组。
- 字段顺序把「分类」放在「标签」前，符合"先决定归类、再补关键词"的心智。

### 3.3 分类索引页（`src/pages/tags/index.astro`）

- 统计口径从 `post.data.tags` 改为 `post.data.categories`。
- **「未分类 (N)」卡片固定排第一**（N=0 也显示），随后按白名单顺序列分类，`0 篇` 的也列出并置灰（一眼能看到有哪些分类可用，方便回填）。
- 链接：分类 → `/tags/<分类>/`；未分类 → `/tags/未分类/`。
- 页面标题「分类标签 / 按主题探索文章。」保持不变。

### 3.4 分类详情页（`src/pages/tags/[tag].astro`）

```astro
export async function getStaticPaths() {
  return [...CATEGORIES, UNCATEGORIZED].map((tag) => ({ params: { tag } }));
}

const { tag } = Astro.params;
const posts = await getCollection("blog", (post) => {
  const cats = post.data.categories ?? [];
  return tag === UNCATEGORIZED ? cats.length === 0 : cats.includes(tag);
});
```

- 用白名单生成路径 → 4 个分类页即使 0 篇也存在（沿用现有"该分类下暂无文章"空态）。
- **不在白名单里的旧标签路径不再生成**（自动 404）。未分类页描述文案改成"还没归类的文章"。

### 3.5 文章详情页（`src/layouts/BlogPost.astro`）

props 是 `CollectionEntry<"blog">["data"]`，`categories` 随 `{...post.data}` 自动传入，`[...slug].astro` 不用改。

```astro
const { title, description, pubDate, updatedDate, categories = [], tags = [], headings = [] } = Astro.props;
// 同篇里分类与标签重名时去重，避免显示两遍
const displayTags = tags.filter((t) => !categories.includes(t));
```

渲染成两行，带小标签前缀，视觉上区分"能点 / 不能点"：

```
分类   #技术笔记          ← <a> 可点；没有分类时显示 <a>#未分类</a>
标签   ES6  Vue  Nginx    ← <span> 不可点、弱化
```

样式：可点分类复用现有 `.tag`；新增 `.tag-muted`（去 hover 位移、降透明度、`cursor: default`）；`displayTags` 为空时不渲染「标签」行。

### 3.6 RSS（`src/pages/rss.xml.ts`）

每个 item 增加 `categories: post.data.categories`（空数组不输出），`tags` 不输出。

### 3.7 现有 12 篇文章：**零改动**

`categories` 缺失 → schema `.default([])` → 全部自动进入未分类；现有 `tags` 原样保留，自动变成"仅展示"。

> 不批量写 `categories: []`，那会白改 12 个文件、污染 diff 与历史。

### 3.8 旧标签 URL

原 16 个 `/tags/<标签>/` 页面全部消失 → 旧链接 404。

- **默认按"接受 404"执行**（个人博客、这些页面几乎不会被外链引用；中文标签名做 301 需要百分号编码的 source，本地无法完整验证）。
- 备选：在 `astro.config.mjs` 的 `redirects` 里给这 16 个名字逐条加 301 → `/tags/`。4 个白名单分类与 `/tags/未分类/` 的 URL 不受影响。

- 新建本文档 `docs/分类标签体系改造方案.md`。
- 更新 `docs/博文编写实施文档.md`：同步 `config.yml` 片段、写作流程加"分类可留空 = 未分类，之后回填"。
- 更新 `src/content/blog/blog-framework.md`：它第 76 行写着"category 并入 tags"（正好是这次改造的反面），第 2 节内容组织说明要改成"分类 vs 仅展示标签"。

## 五、边界情况与失败模式

| 情况 | 表现 | 处理 |
|---|---|---|
| Sveltia 把空 select 写成 `''` | 构建报数组类型错误 | `.preprocess` 归一化兜住（同 `updatedDate` 的既有坑） |
| VSCode 手写非白名单分类名 | 构建失败并报非法值 | 有意为之，改词表或改正拼写 |
| 分类超过 3 个 | 构建失败 | CMS `max: 3` 先拦，schema 双保险 |
| 分类名也出现在 `tags` | 详情页显示两遍 | 渲染时 `displayTags` 去重 |
| 某分类 0 篇文章 | 页面存在但空 | 索引页置灰 + 详情页空态文案 |
| 以后新增/改名分类 | 忘同步两处 → 构建失败或 CMS 选项缺失 | 改 `src/config.ts` + `config.yml` 两处 |
| 分类名含 `/` 或 `#` | 破坏 `/tags/<分类>/` 路由 | 白名单里禁止 |
| `tags` 全部留空 | 详情页不显示标签行 | `.default([])` 正常 |

### 9.3 遗留事项

1. **旧标签页现在是 404**（16 个）。按方案的默认假设不做 301；若你希望旧链接跳到 `/tags/`，可在 `astro.config.mjs` 的 `redirects` 里逐条补静态 301（中文标签名需要百分号编码，且要部署后验证）。
2. **12 篇文章仍全部是「未分类」**，这是本次刻意的结果——归类由你自己在 `/tags/未分类/` 里挑文章、勾分类完成。
3. **CMS 侧未做联调**（`/admin/` 需要你的 GitHub PAT）。建议你点一遍：新建文章时「分类」留空应能保存；再编辑勾一个分类保存后 frontmatter 出现 `categories`。
4. 以后**新增/改名分类要改两处**：`src/config.ts` 的 `CATEGORIES` 与 `public/admin/config.yml` 里 select 的 `options`，两处必须一致，否则会出现"构建失败"或"CMS 里选不到"。
