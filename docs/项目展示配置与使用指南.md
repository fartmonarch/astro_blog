# 项目展示配置与使用指南

面向「怎么用」和「改哪里」，不讲 Astro 基础。日常要做的就是**在 `/admin/` 里增删改项目**。
（开发实现细节见 [《项目展示功能手册.md》](./项目展示功能手册.md)。）

## 一、它长什么样

| 位置 | 内容 |
|---|---|
| 导航栏 | 「项目」在首页和归档之间，指向 `/projects/` |
| 首页 | 「项目」模块：**只放精选的项目**，最多 4 张卡片（一行两个），底部「全部项目 →」 |
| `/projects/` | **全部项目**，一行两个卡片；顶部一排按技术栈筛选的按钮 |

就这三处。**没有项目详情页**——卡片本身就是全部信息，卡片不跳转到站内任何页面。

卡片上依次是：图标、项目名称 + **精选徽章**（勾了精选才有）+ **状态徽章**、平台图标、简介、技术栈标签、底部的链接入口。

## 二、加一个项目（日常操作）

1. 打开 <https://www.fartmonarch.xyz/admin/>，登录（见《Sveltia CMS 配置与使用指南.md》3.1）
2. 左侧选 **项目** → 右上 **New 项目**
3. 填字段（下表）
4. 右上 **Publish** → 自动 commit 到 `main` → Vercel 重新部署

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | 是 | 卡片标题。**同时会被用作文件名**，含中文没关系（项目没有独立 URL） |
| 项目简介 | 是 | 卡片上的一段话。超过 3 行会被截断显示（`-webkit-line-clamp`），所以别写太长 |
| 状态 | 是 | `维护中` / `开发中` / `已归档`，卡片上项目名旁边的徽章 |
| 平台 | 否 | `github` / `gitee` / `npm` 多选。选中几个就在卡片上显示几个平台图标 |
| 精选 | 否 | **只有勾了精选的项目才会出现在首页。** 不勾也能在 `/projects/` 里看到，卡片上也不会显示「精选」徽章 |
| 技术栈标签 | 否 | **一个文本框，自己用逗号分隔**，见第三节 |
| 封面图 URL | 否 | 项目图标，正方形/圆形都可以，见第四节；留空则显示项目名的第一个字 |
| 项目链接 | 否 | 一个折叠分组，里面是**上线地址 / 源码仓库 / npm 包地址**三个独立字段 |
| 备注（正文） | 否 | 卡片上不展示，留作写备注 |

**三个链接各自独立**：填了哪个就显示哪个入口按钮，三个都留空则不显示链接区。三个都可以单独填、单独留空，互不影响。

## 三、技术栈标签：为什么是文本框

**没有白名单。** 你想要 `React, JSON, Viewer, 阮周刊`，就在「技术栈标签」里照这样写一行，构建时会切成 4 个标签。

切分规则（`src/content.config.ts` 里的 `techStackArray`）：

- 分隔符：半角逗号 `,`、全角逗号 `，`、顿号 `、` 都行
- 每段去掉首尾空格；空的段被丢掉；重复的只留一个
- 于是 `React, , JSON，Vue、React` → `["React", "JSON", "Vue"]`

**筛选按钮是自动汇总的**：`/projects/` 顶部的按钮由所有项目里实际出现过的技术栈算出，不另设词表。所以：

- 新加一个技术栈，只要在某个项目里写出来，按钮自动出现，**不用改任何配置**
- 某个技术栈没有任何项目用到，按钮就不存在

## 四、卡片图标

卡片左侧那个图标位有两种来源：

- **「封面图 URL」填了值** → 显示这张图。**正方形、无边框、圆角 8px、`object-fit: contain`**，所以方形 logo 和圆形 logo 都能完整展示，长图/竖图也只是缩小、不会被裁掉两边。
- **留空** → 显示项目名称的**第一个字**（「沫之白的小窝」显示「沫」），琥珀色字。

**图标底色就是卡片底色**（`background: var(--card-bg)`），所以图标和卡片完全融合，看不到一个方块印子；有图时底色被图片盖住，等于"背景由上传的图片自己决定"。

想调图标大小，改 `src/components/ProjectCard.astro` 里 `.icon` 的 `--icon-size`（默认 `64px`）与 `--icon-font`（默认 `1.6rem`，只管那个首字）。

> 两条别改回去：
> 1. **别给 `.icon` 加 `border`**——圆形透明底 PNG 加了边框会变成"圆里套一个方框"。
> 2. **别把 `object-fit` 改回 `cover`**——那会把长图/竖图裁掉两边，失去"什么形状都能正常展示"。

图要先用 PicGo 传到 COS 拿外链（见《图片上传COS操作指南.md》），再粘到「封面图 URL」；CMS 里没有上传按钮。

### 平台图标为什么不用 astro-icon

平台角标（GitHub / Gitee / npm）和卡片底部的入口图标都内联在 `src/components/BrandIcon.astro` 里，**没有走项目原有的 astro-icon**。

原因：astro-icon 的本地图标集（`src/icons/`）在本项目里加载不出来——它的 Vite 插件把异常吞掉了，虚拟模块会导出 `undefined`，页面于是报 `Unable to load the "local" icon set!`。卡片上就这 5 个图标，直接内联 path 最省事也最稳。

**所以不要再往 `src/icons/` 放图标**，那个机制在当前依赖环境下是坏的。要加新图标就往 `BrandIcon.astro` 的 `paths` 里加一条，并在 `Props` 的联合类型里补上名字。

## 五、精选、排序与首页

### 首页只放精选，且最多 4 个

首页的「项目」模块**只统计勾了「精选」的项目**，而且**最多显示 4 张卡片**：

- 有精选 → 展示这些精选项目（最多 `PROJECTS_ON_HOME` 条，默认 4，超出部分只在 `/projects/` 里出现）
- **一条精选都没有 → 整个模块隐藏**（首页不会出现空标题）

所以「精选」就是上首页的门槛，`/projects/` 页面则永远展示全部项目、不受精选和数量限制影响。

想改首页展示数量：`src/config.ts` 的 `PROJECTS_ON_HOME`。

### 顺序

两个页面共用同一套排序规则（`src/pages/index.astro` 与 `src/pages/projects/index.astro` 里各有一份）：

```
精选的排前面 → 然后按项目名称（中文拼音）排序
```

### 已知限制：没有手动拖拽排序

Sveltia 目前不支持文件夹集合的手动排序（官方 issue [sveltia/sveltia-cms#214](https://github.com/sveltia/sveltia-cms/issues/214) 还没落地），`src/` 目录下的文件名也不参与排序。想让某个项目排在前面，只有把它标成「精选」（同时也就意味着它会进首页）。

## 六、改配置要动哪几个文件

和其他集合一样，字段是两边各写一份，**必须同步**：

| 想改什么 | 要动哪些文件 |
|---|---|
| 加/删/改字段 | `public/admin/config.yml`（CMS 表单） + `src/content.config.ts`（Astro schema） |
| 改状态选项（维护中…） | 上面两个 + `src/config.ts` 的 `PROJECT_STATUSES` |
| 改平台选项（github…） | `public/admin/config.yml` 里的 `options`、`src/content.config.ts` 里的 `z.enum`、`src/config.ts` 的 `PROJECT_PLATFORMS`、`src/components/BrandIcon.astro`（补图标） |
| 改首页展示张数 | `src/config.ts` 的 `PROJECTS_ON_HOME` |
| 改卡片样式 / 图标大小 | `src/components/ProjectCard.astro`（卡片本身，图标大小在 `.icon` 的 `--icon-size`） |
| 换平台图标 | `src/components/BrandIcon.astro` 的 `paths` 里加/换一条 + 补 `Props` 联合类型。**不要再往 `src/icons/` 放**，见第四节 |

## 七、排错

| 现象 | 原因 / 处理 |
|---|---|
| 首页看不到某个项目 | 它没勾「精选」。勾上（或直接改 frontmatter 的 `featured: true`）即可 |
| 首页整个「项目」模块不见了 | 一条精选都没有。这是设计如此；去勾几个精选 |
| 首页精选项目超过 4 个但只显示了 4 个 | 这是设计如此（首页最多 4 张）。想看全部去 `/projects/`；想改数量改 `src/config.ts` 的 `PROJECTS_ON_HOME` |
| 改了 md、页面却不变（状态或内容对不上） | 开发服务器的内容缓存是旧的。`npx astro dev stop` 后重新 `npx astro dev` 即可；`npm run build` 直接读盘，不受影响 |
| 构建报 `Invalid enum value` 并点名某个值 | 状态或平台的**拼写**与代码里的枚举不一致。照着报错里的合法值改 |
| CMS 里存得进、构建失败 | `config.yml` 加了字段但 `src/content.config.ts` 没同步 |
| 卡片上的技术栈没切开 | 分隔符用的是别的东西（如分号）。只认 `,` `，` `、` |
| 卡片图标不是预期的图 | 填的 URL 打不开，或已停用。换成可访问的方形/圆形图 |
| 图完全不显示 | 外链失效或没带 `https://`。图标是直接 `<img src>`，没有本地兜底 |
| 图标被裁掉一边 | 有人把 `object-fit` 改成 `cover` 了，应该是 `contain` |
| 图标外有个方块/圆框印子 | 有人给 `.icon` 加了 `border`，或把背景改成了 `--dark`。应该无 border + `background: var(--card-bg)` |
| 控制台报 `Unable to load the "local" icon set!` | astro-icon 的本地图标集（`src/icons/`）坏了，不是项目功能的问题。卡片图标已不走它；若还有别处用到 `<Icon>`（如 `Profile.astro` 的 mdi 图标）不受影响 |
| 顶部没有筛选按钮 | 所有项目的技术栈都是空的，按钮排被整段隐藏了 |
| 点筛选后地址栏没变化 | 这是设计如此：筛选只改 `?tech=` 并 `replaceState`，不刷新页面 |

## 八、这些决策是为什么

| 决策 | 原因 |
|---|---|
| 不做详情页 | 卡片一行两个已经装得下全部信息；少一个路由、少一份正文要维护 |
| 首页要「精选」才上，`/projects/` 全量 | 首页是门面，只摆最好的几个；完整清单放在项目页，两处职责分开 |
| 卡片图标做成 64px 小图标而不是宽幅封面 | 项目列表更像通讯录而不是作品画廊；图标小、信息密度高，一行两个也不会显得空 |
| 图标底色 = 卡片底色、不要边框 | 图标和卡片融合，不出现"方块印子"；有图时由图片自己决定观感 |
| 品牌图标内联而不走 astro-icon | astro-icon 的本地图标集在当前依赖环境下加载失败（见第四节），内联 5 个 path 零依赖、零不确定性 |
| 技术栈不用多选控件 | 多选控件要先定死选项，加一个技术栈就得改 CMS 配置。自由文本零维护 |
| 不抓 GitHub 星标 / npm 下载量 | 构建不再依赖外网和 token，Vercel 构建稳定；代价是数字要手动更新（本期干脆不展示数字） |
| 链接是三个固定字段而不是任意列表 | 就这三个去处（上线地址、源码、npm），固定字段在 CMS 里有清晰的标签，比"填一个列表"更不容易填错 |
| 排序不依赖日期 | 项目没有"发布日期"的语义；精选 + 名称既可控又可复现（不依赖文件系统返回顺序） |
